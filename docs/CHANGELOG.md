## v1.7.0（2026-09-04）

- **适配 harness v0.1.2-alpha.1 launch token 鉴权**：新版 harness 启动时生成一次性 token，裸 URL 一律 401——壳改为从 `dsh web` 启动输出（stdout `dsh web: <URL>` 行）抓取带 token 的访问地址，窗口加载、「浏览器打开」全部改用该地址；解析失败降级为明确的错误卡片而非天书
- **归档「远程接管外部 dsh」**：launch token 只存在于拉起进程的 stdout，外部进程无从取得，接管路径根本性失效——探测/身份验证/清理代码全部注释保留，3080 被占用改为直接报错提示；「退出APP（保留服务）」菜单项随之删除（存在意义即配合接管），接管心跳一并退役
- **会话完成通知暂时禁用**：harness 事件流端点 `/api/events.host` 被删除，替换为多路复用 WebSocket `/api/remote.mux`（协议未文档化，C# 侧复刻成本高）——设置页开关隐藏，`CompletionNotifier`（含已实现的 token→cookie 握手）保留待按新协议重写
- **局域网共享暂时禁用**：代理链路未适配 launch token，设置页入口隐藏，Kestrel+YARP 代理代码完整保留待适配

## v1.6.0（2026-08-26）

- **局域网共享（LAN Share）**：设置页一键开启后，手机/其他电脑浏览器访问 `http://电脑IP:3081/?key=密钥` 即可遥控同一 Harness——会话状态全在服务端、事件流全客户端广播，双端实时同步、手机可直接发指令；token 门禁（首验种 Cookie、常量时间比较）防蹭网，错误一律 403
- 共享代理由壳内 Kestrel + YARP 实现：转发时改写 Host/Origin 头通过 harness browser-trust 围栏；`crypto.randomUUID` polyfill 注入页面入口（修补非安全上下文下前端 RPC 全灭）；HTTP/SSE/WebSocket 全透传
- 远端安全边界：改设置/凭据、预设写操作、本机原生对话框、内网探测（llm.discoverModels）在 LAN 侧仍 403，只读与聊天控制放行
- 设置页「局域网共享」区块：开关、含密钥完整地址一键复制 + **网址二维码（手机扫码直达，像素按模块数自适应防缩放失真）**、端口修改（失焦保存）、重新生成密钥（旧密钥立即失效）、防火墙放行按钮（netsh 提权）
- 托盘悬停提示新增 `LAN :端口` 段（共享运行时显示）
- 自包含单 exe 打包纳入 ASP.NET Core 运行时（Kestrel/YARP 依赖），体积约 +25MB

## v1.5.1（2026-08-26）

- 余额/额度获取失败可视化分级：顶栏失败状态三分支——未授权（凭据文件在）弱色「—」、网络连续失败红色「NET_ERR」、业务失败（Key 无效等）红色「ERROR」，悬停 tooltip 均带具体原因
- 失败边沿提醒：成功→失败跳变时提醒一次（窗口可见弹红色状态卡，托盘化弹系统气泡，点击气泡恢复窗口并打开设置页），恢复后复位；网络类失败严格连续 2 次才弹（单次抖动静默保留旧值），业务失败立即提醒，轮询不再反复轰炸
- 一键补授权：检测到 dsh 凭据文件但未授权时，点击顶栏余额区直接弹授权确认框，允许后立即刷新——修复「先开余额开关、凭据文件后出现」场景永不提示授权的盲区
- Key 缺失错误文案分层：按「未授权（文件在）/ 文件缺失 / 键未读到 / 未配置」四种情形给出具体提示，排查不再被笼统的「未配置 API Key」误导
- 启动 dsh 服务时不再自动打开浏览器（--no-open），只弹桌面壳窗口
- 修复额度监管失效：凭据读取兼容 dsh rc.8 嵌套格式（version: 1 + refs:），Kimi 5h 窗口兼容 remaining 字段
